0. 📦 INSTALAR Y USAR CON CONTENEDOR (lo que usa quien instala AXIOMA)
════════════════════════════════════════════════════════════════════════════════
No hace falta saber programar: el instalador y el lanzador se abren con DOBLE CLIC.

  ./instalar/instalar_axioma.sh       # UNA SOLA VEZ: comprueba Docker, arma la imagen,
                                      # deja el acceso directo en el menú y arranca
  ./instalar/iniciar_axioma.sh        # cada vez: enciende y ABRE EL NAVEGADOR
  ./instalar/iniciar_axioma.sh --detener   # apagar todo
  ./instalar/iniciar_axioma.sh --dry-run   # ver qué haría, sin tocar nada

  · Decide solo el Ollama: si el equipo ya tiene uno andando, usa ese; si no, levanta el que
    viene con AXIOMA (perfil `ollama-local`, modelos en un volumen).
  · Puerto distinto:  AXIOMA_PUERTO=8090 ./instalar/iniciar_axioma.sh

WINDOWS (PowerShell; hace falta Docker Desktop con WSL 2). Los mismos guiones, con otros nombres:

  powershell -NoProfile -ExecutionPolicy Bypass -File .\instalar\instalar_axioma.ps1   # UNA VEZ
  powershell -NoProfile -ExecutionPolicy Bypass -File .\instalar\iniciar_axioma.ps1   # cada vez
  .\instalar\iniciar_axioma.ps1 -Detener      # apagar todo
  .\instalar\iniciar_axioma.ps1 -Ensayo       # ver qué haría, sin tocar nada

  · El instalador deja un acceso directo «AXIOMA» en el menú Inicio y en el Escritorio (así no
    hace falta abrir PowerShell nunca más).
  · En Windows NO se usa `network_mode: host` (no existe ahí): va el servicio `axioma-puente`
    (perfil `puente`, publica el 8080 y llega al Ollama del equipo por `host.docker.internal`).
    Consecuencia: el puerto es 8080 fijo y la VOZ todavía no está disponible en Windows.
  · El servicio se nombra UNO POR UNO: `docker compose --profile puente up -d axioma-puente`
    (`... axioma-puente ollama` si además hay que levantar el Ollama propio). Medido el
    2026-10-06: sin nombrarlo, `--profile puente` levanta ADEMÁS `axioma`, que usa la red del
    equipo; los dos pelean por el 8080 y `axioma` queda en bucle de reinicios.
  · Pendiente: los guiones de Windows están escritos y cubiertos por pruebas de estructura, pero
    TODAVÍA NO se probaron en un Windows real (no había ninguno a mano).

Contenedor (Docker Compose):

  docker compose up -d --build        # encender (armando la imagen)
  docker compose logs -f axioma       # ver qué está pasando
  docker compose down                 # apagar
  docker compose --profile ollama-local up -d    # Ollama DENTRO del contenedor
  docker compose --profile voz up -d voz         # servicio de VOZ (Rafael)
  docker compose --profile voz stop voz          # apagarlo

¿Qué le falta al equipo? (lo mismo que muestra la pantalla 🧩, pero por consola)

  docker compose exec axioma python -m src.core.preflight          # informe legible
  docker compose exec axioma python -m src.core.preflight --json   # para programas
  docker compose exec axioma python -m src.core.preflight --instalar        # baja lo que falta
  docker compose exec axioma python -m src.core.preflight --instalar --todo # incluye opcionales

Tus claves de API (son TUYAS: nunca viajan en la imagen)

  docker compose exec axioma python -m src.core.apikeys            # carga guiada (una por una)
  docker compose exec axioma python -m src.core.apikeys --listar   # estado, sin mostrar valores

Verificaciones del proyecto (para quien quiera comprobar que todo está bien)

  tools/verificar_imagen.sh                    # compila, MIDE el tamaño, corre la suite adentro
  tools/verificar_imagen.sh --solo-plan        # muestra los pasos sin ejecutar
  venv/bin/python tools/verificar_primer_arranque.py   # guía de primer arranque en navegador real

1.1 💬 COMANDOS DEL CHAT (UI web / --chat) — v0.6.8pp..uu
────────────────────────────────────────────────────────────────────────────────
/plan <consulta compleja>   # F3 opt-in (v0.6.8rr): descompone la tarea
                            # (heurístico, gratis) y ejecuta un pipeline de
                            # ≤2 pasos: rol principal (coder/researcher) +
                            # validador FINAL. Coste real en CPU: 2 generaciones
                            # LLM (~1-3 min) — por eso es opt-in explícito.
                            # Ej:
                            #   /plan analizá tools/auditor y generá un reporte
                            #        de mejoras de seguridad en markdown
                            #   /plan generá un programa completo que procese CSV
                            # Si la consulta es atómica o de chat puro → se
                            # procesa por la ruta normal (sin pipeline).
                            # /plan solo → mensaje de uso.

# Activación AUTOMÁTICA del pipeline (opcional, default OFF):
#   plan_pipeline_enabled=true  → consultas ≥40 chars descomponibles corren
#   pipeline tras clasificar. plan_max_steps=2 (cap de pasos).
#   Config en config/settings.py o variables .env (settings pydantic).

# Consultas de ARCHIVOS con grounding local (v0.6.8pp — sin LLM, <1 s):
#   usá fs_search para buscar qué archivos de tools/auditor hablan del SCORE
#   qué archivos de src/core mencionan validator
#   usá fs_list para listar la carpeta tools/auditor
#   (respuesta con sources reales vía grep local del contenido)
# v0.6.8ss:
#   - Validador: extracción de score tolerante a markdown (**SCORE:** 10.0 ya
#     parsea); skip de validación en respuestas ≤80 chars o con sources reales
#     (eventos "Chat validation SKIPPED (A1)" en logs). Single-pass se mantiene.
#   - Streaming de tokens a la UI: stream_chat_tokens=true (default OFF; probar
#     en vivo antes de activar). Con OFF la respuesta llega completa como siempre.
#   - Tools del chat: se activan por verbo/contexto (buscá/noticia/archivo/fs_*…);
#     chat puro va directo a 1 generación (B2).
# v0.6.9p — canal de imágenes + fuentes + calculadora:
#   🖼️ ADJUNTAR IMAGEN (Web): botón 📎 → PNG/JPG/WebP/GIF/BMP → responde
#     qwen3-vl:4b bajo demanda (~45-55 s en CPU; desaloja qwen3:8b de Ollama
#     y libera RAM al terminar). Instrucción vacía → la describe.
#   - OCR HÍBRIDO: si pedís leer/transcribir ("¿qué dice?", "copiá el texto")
#     se usa Tesseract LOCAL primero (dependencia de SISTEMA: sudo apt
#     install tesseract-ocr tesseract-ocr-spa). Si confianza ≥
#     vision_ocr_min_conf (60) → texto exacto en ~0 s; si no → VLM.
#     Preprocesado adaptativo: contraste bajo → autocontraste; imagen <400 px
#     → upscale 2x; tope vision_num_predict (512) evita generaciones colgadas.
#   - LÍMITES medidos: colores/formas/conteo/escenas/ruido OK; fotos reales
#     clasifican persona/animal/vehículo/vegetación (tests E2E con assets en
#     tests/assets/vision); texto muy chico/embebido → inestable (mitigado por
#     Tesseract); fotos complejas/rostros → acotados por el hardware (4B).
#   📎 FUENTES/CITAS: respuestas grounded (fs_search/folder-analysis) muestran
#     el bloque "📎 Fuentes (N)" bajo la burbuja (Web) y la lista en el CLI.
#   🧮 CALCULADORA: pedí una cuenta ("¿cuánto es 15% de 4200?") — tool MCP
#     determinística (AST, sin eval(), sin red).
#   Settings nuevos (config/settings.py): vision_num_predict ·
#     vision_preprocess_enabled · vision_ocr_enabled · vision_ocr_min_conf.

── 2.8 NOTAS ÚTILES DE LA SUITE ────────────────────────────────────────────────
· La suite NO requiere Ollama ni hardware real (todo mockeado) → corre en ~5 s.
· Cada archivo de test respeta el límite de 750 líneas (máx. real: 412).
· tests/axioma_report.py = generador del reporte (no es un test, no se ejecuta solo).
· tests/suite_utils.py = helpers compartidos (import_safe, api_check…).
· Los 3 diagnósticos de tests/ (audio, code_contract_e2e, rafael_bridge) requieren
  entorno real; por eso pytest los ignora (collect_ignore en tests/conftest.py).
· El check "PromotionGate" copia una sombra del proyecto a /tmp (excluye data/,
  logs/, cache/ y venv desde 2026-08-25). Si /tmp (tmpfs) está 100 % lleno por
  otros procesos, ese check puede reportar FAIL de entorno (no es bug del código)
  — libere espacio en /tmp y vuelva a ejecutar.
· Comandos con venv sin activar:
    venv/bin/python -m pytest tests/
· Ver ayuda completa de pytest:
